# misteRus Dashboard Cards

Учебный SPA-дашборд для управления банковскими картами: список карт, выбор активной карты, блокировка, быстрые переводы, история операций, фильтры и аналитика.

Проект развивается последовательно от лабораторной к лабораторной. Текущее состояние — **ЛР №8: Unit и e2e-тестирование**. Приложение не работает с реальным банком: данные приходят с локального mock-сервера и хранятся в памяти Node.js.

## Что умеет приложение

- **Карты:** список карт, баланс, тип и срок действия, выбор активной карты, блокировка и разблокировка, маскировка номера, детали в модальном окне.
- **Переводы:** между своими картами в одной валюте, с проверкой блокировки, суммы и остатка; создаёт две операции — списание и зачисление.
- **Операции:** история по активной карте и отдельная страница, фильтр «Все / Доходы / Расходы», сортировка от новых к старым, детали операции.
- **Аналитика:** статистика по картам и валютам, диаграммы доходов и расходов по категориям.
- **Надёжность:** индикаторы загрузки, обработка сетевых ошибок, повтор запроса, страница 404, базовая доступность интерфейса.

Внешний вид сделан на обычном CSS без UI-библиотек.

## Быстрый старт

Нужны Node.js `^20.19.0` или `>=22.12.0` и npm.

```bash
npm ci
```

В первом терминале запустить mock API:

```bash
npm run server
```

API будет доступен на `http://localhost:3001`.

Во втором терминале запустить клиент:

```bash
npm run dev
```

Сайт будет доступен на `http://localhost:5173`.

Без запущенного mock-сервера интерфейс откроется, но покажет ошибку загрузки данных.

## Пользовательские сценарии

### Выбор карты

Карточка карты кликабельна с мыши и клавиатуры. После выбора обновляются баланс, список операций и данные в `localStorage`. Если сохранённая карта больше не существует, автоматически выбирается первая из загруженных.

### Блокировка карты

Кнопка в карточке отправляет `POST /api/cards/:id/toggle-block`. После ответа RTK Query обновляет кеш карт: меняется статус карты и доступность перевода.

### Перевод

Пользователь выбирает карту-источник и получателя, вводит сумму и отправляет форму. Сервер проверяет правила перевода, возвращает обновлённые карты и две операции. В интерфейсе появляется уведомление, а балансы и история обновляются автоматически.

### Фильтрация и аналитика

Фильтр хранится в Redux и в `localStorage`. `useActiveCard` применяет его к операциям, а `buildOperationsStats` пересчитывает сводку и диаграммы для страницы `/operations`.

### Восстановление после ошибки

Если mock-сервер недоступен, приложение показывает сообщение об ошибке. Кнопка «Обновить данные» повторяет запросы. После повторного запуска сервера данные возвращаются без перезагрузки страницы.

## Логика работы

### Загрузка данных

1. `useBankData` вызывает хуки RTK Query `useGetCardsQuery` и `useGetOperationsQuery`.
2. RTK Query через собственный `axiosBaseQuery` обращается к `apiClient`.
3. Ответ приходит как `unknown` и проверяется guard-функциями `isCardArray` / `isOperationArray`.
4. Проверенные данные кешируются RTK Query и попадают в страницы через хуки.
5. Если структура ответа неверная, запрос завершается ошибкой, а не передаёт невалидные данные в UI.

### Блокировка карты

`CardItem` вызывает mutation `toggleCardBlock`. После успешного ответа RTK Query инвалидирует тег списка карт, поэтому балансы и статусы обновляются автоматически.

### Перевод

`QuickTransfer` проверяет:

- выбраны ли карты-источник и получатель;
- не одна ли это карта;
- не заблокированы ли карты;
- совпадают ли валюты;
- положительная ли сумма;
- достаточно ли средств.

Сумма принимается с точкой или запятой и округляется до копеек. Сервер возвращает обновлённые карты и две новые операции. После mutation инвалидируются теги `Card` и `Operation`, поэтому интерфейс сразу показывает новые балансы и историю.

### Фильтрация и аналитика

`filterSlice` хранит значение фильтра, а `useActiveCard` применяет его к операциям активной карты и сортирует результат. `buildOperationsStats` считает доходы, расходы, итоги по картам и данные для диаграмм. Для категорийных диаграмм доллары переводятся в рубли по фиксированному курсу; статистика по валютам остаётся раздельной.

### LocalStorage

| Ключ | Назначение |
| --- | --- |
| `app_active_card` | ID активной карты |
| `app_filter` | Текущий фильтр операций |
| `last_transfer_amount` | Последняя введённая сумма перевода |
| `last_transfer_target` | Последняя выбранная карта-получатель |

Некорректные сохранённые значения не ломают приложение: используется значение по умолчанию.

## Типы и данные

Все доменные типы находятся в `src/shared/types/index.ts`.

### `Card`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `number` | Идентификатор карты |
| `number` | `string` | Номер карты; в UI показываются только последние 4 цифры |
| `balance` | `number` | Доступный остаток |
| `currency` | `string` | Валюта: `₽` или `$` |
| `isBlocked` | `boolean` | Статус блокировки |
| `expiry` | `string` | Срок действия в формате `MM/YY` |
| `type` | `'Mir' \| 'Visa' \| 'MasterCard'` | Платёжная система |

### `Operation`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `number` | Идентификатор операции |
| `cardId` | `number` | Карта, к которой относится операция |
| `title` | `string` | Название, по которому определяется категория |
| `amount` | `number` | Сумма: `+` для дохода, `-` для расхода |
| `date` | `string` | Дата операции |
| `createdAt` | `string?` | Точное время; если отсутствует, используется `date` |

### Остальные типы

| Тип | Назначение |
| --- | --- |
| `FilterValue` | `all`, `income` или `expense` |
| `TransferPayload` | `fromCardId`, `toCardId`, `amount` для запроса перевода |
| `TransferResult` | Обновлённые карты и две созданные операции |
| `LoadingState` | Union состояний загрузки: `idle`, `loading`, `success`, `error` |
| `TransferState` | Discriminated union для состояний формы перевода |

В проекте используются утилитарные типы `Pick`, `Omit`, `Record`, дженерик `useLocalStorage<T>` и дженерик-запрос `request<T>`. Внешние данные всегда сначала воспринимаются как `unknown`, а не приводятся через `as`.

## API

Mock-сервер на Express предоставляет четыре endpoint-а:

| Метод | Путь | Что делает |
| --- | --- | --- |
| `GET` | `/api/cards` | Возвращает карты |
| `GET` | `/api/operations` | Возвращает операции |
| `POST` | `/api/cards/:id/toggle-block` | Меняет статус блокировки |
| `POST` | `/api/transfers` | Выполняет перевод |

Сервер проверяет существование карт, совпадение валют, блокировку, достаточность средств и корректность суммы. Ошибки возвращаются как `400` или `404` с полем `error`.

RTK Query использует теги `Card` и `Operation`. Mutation инвалидируют списки, поэтому после изменений данные перезагружаются без ручного обновления страницы.

## Состояние и кеш

- Redux хранит активную карту и фильтр.
- RTK Query хранит кеш карт и операций.
- Локальное состояние компонентов отвечает за модалки, поля формы и уведомления.
- `localStorage` сохраняет пользовательские настройки и данные последнего перевода.

Такое разделение позволяет не дублировать серверные данные в Redux и не терять пользовательский выбор между перезагрузками.

## Тесты

### Unit-тесты

Используются `jest` и `ts-jest`. Тесты лежат в `src/**/__tests__` рядом с тестируемыми слоями и попадают под общую проверку типов.

Покрыты:

- чистые утилиты форматирования, сортировки, поиска, категорий и статистики;
- guard-функции и редьюсер фильтра;
- асинхронные эндпоинты RTK Query: успех, ошибка, неверный формат ответа;
- обычные, пустые и невалидные данные.

В async-тестах подменяется только `apiClient.request`, то есть ответ сервера. Сами эндпоинты и store остаются настоящими.

```bash
npm test
```

Результат: **9 файлов, 76 тестов**.

### E2E-тесты

Playwright открывает реальный сайт в Chromium и выполняет действия пользователя: переходы, клики, выбор карты, ввод суммы и проверку текста на странице.

Сценарии в `e2e/dashboard.spec.ts`:

1. Загрузка карт и операций.
2. Блокировка и разблокировка карты.
3. Перевод с проверкой уведомления и новой операции.
4. Фильтрация доходов и расходов.
5. Страница 404.

`playwright.config.ts` сам поднимает mock API и Vite через `webServer`, поэтому отдельно запускать серверы перед e2e-тестами не нужно.

На новой машине перед первым запуском:

```bash
npx playwright install chromium
```

Запуск:

```bash
npm run test:e2e
```

Результат: **5 сценариев**.

## Как расширять

- **Новое поле сущности:** обновить тип, guard-функцию, mock-данные и компоненты; затем запустить `npm run typecheck`.
- **Новый запрос:** описать типы, добавить endpoint в `bankApiSlice`, указать теги и использовать сгенерированный хук.
- **Новая страница:** создать компонент в `src/pages`, добавить маршрут в `App.tsx` и ссылку в навигации.
- **Новая утилита:** положить её в `src/shared/lib` и сохранить как чистую функцию без React-зависимостей, если это возможно.

## Диагностика

| Проблема | Что проверить |
| --- | --- |
| Данные не загружаются | Запущен ли `npm run server`, доступен ли `/api/cards`, совпадает ли `API_URL` |
| Порт `3001` занят | Запустить `PORT=3002 npm run server` и изменить `API_URL` |
| Старые данные после изменения сервера | Перезапустить mock-сервер: у него нет hot reload |
| Ошибки типов после обновления пакетов | Проверить версии `typescript` и `typescript-eslint` через `npm ls` |
| Пустые диаграммы | Есть ли операции и совпадают ли `cardId` с ID карт |
| Перевод недоступен | Проверить выбор карт, блокировку, валюту, сумму и остаток |
| e2e-тесты не запускаются | Выполнить `npx playwright install chromium` |

## Ограничения

- Данные хранятся только в памяти mock-сервера и сбрасываются после его перезапуска.
- Нет авторизации, базы данных и реального банковского API.
- Переводы возможны только между картами одной валюты.
- `API_URL` задан в коде, без `.env`.
- Нет CI, code splitting и ленивой загрузки страниц.
- Диаграммы сделаны через CSS `conic-gradient`, без библиотеки графиков.
- `localStorage` не синхронизируется между вкладками.
